
# CYVORA Contribution Guidelines

## 1. Development Principles

- Communicate before making major changes.
- Keep code organised and readable.
- Test changes before submitting.
- Never expose sensitive credentials.
- Respect other team members' contributions.

## 2. Branching Rules

Never push directly to main.

Use the following naming conventions:

- feature/feature-name
- fix/bug-name
- docs/documentation-name
- test/test-name

## 3. Commit Messages

Use clear commit messages.

Examples:

- feat: add user authentication
- fix: resolve login validation issue
- docs: update project documentation
- test: add authentication tests
- chore: update project configuration

## 4. Pull Requests

Every contribution must:

1. Be pushed to a separate branch.
2. Include a clear description.
3. Be tested before submission.
4. Pass required automated checks.
5. Receive an appropriate review.

## 5. Security Requirements

- Never commit .env files.
- Never upload private API keys.
- Never share database passwords.
- Use synthetic test data.
- Report security vulnerabilities responsibly.

## 6. Team Collaboration

Discuss conflicting changes before merging.

Keep the main branch stable and functional.
